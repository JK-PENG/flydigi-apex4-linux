# ForceAdapt mode 1 负样本的最小可观察性设计

状态：用户已批准该离线诊断规格；不授权新的实体写入。

## 问题与证据边界

2026-09-23 的 APEX 4/2.4G 实测中，独立 L2/R2 mode 1 写入均返回完整长度、
自动双侧 Normal、虚拟 Edge 恢复，但持握者没有感到阻力。L2 mode 2 曾被感到；
较早的 OW2 R2 mode 2→mode 1 序列也有持握者正样本。不能用旧正样本覆盖
新负样本，也不能据此直接推断 `start=0`、强度、手柄配置或硬件故障。

本次物理输入监视的输出曾因工具结果长度上限截断；已记录的命令起止时间也有
一次包含身份验证准备段。因此输入是否恰好位于实际效果窗口内仍未完整证明。
目前的 `VerifiedTransport.write_effect()` 只证明 15 字节到达操作系统 HID fd，
不证明固件执行或持握者感到。另一份针对 APEX 4 的
[独立协议实测](https://github.com/uiltonlopes/flydigi-space-station-mac/blob/main/docs/protocol.md)
记录 DInput `05 A0 01` 的 Race/Normal 回执；本项目尚未确认其在当前固件/接收器
上的返回形态，不把该记录当成本机 ACK 证据。

## 选择与非目标

1. **选择：有界同 fd 观察 + 完整私有输入日志。** 复用已验证的直写工具、
   `legacy.command_echo()` 和现有 `input-source-watch.py --physical-only`。
   只观察已有命令产生的回复，不新增 vendor 请求、常驻进程或生产依赖。
2. 只用独立 evdev 监视和 shell 起止时刻：改动最少，但无法判断固件是否回了
   `0xA0`，且此前把整条命令窗口错当作实际效果窗口，不足以闭合问题。
3. 直接提高 resistance 强度/更改 match-input：可能更快出现触感，但在接收与
   动作时间未确认时属于扩大实体参数范围；本轮不做。不能自动改通用 translator。

本诊断不写 profile/固件/工厂命令，不切换手柄模式，不改游戏配置，不启用
`generic-safe` 默认，也不把“看到 `0xA0` echo”说成实体触感 PASS。

## 诊断数据流

- 现有工具增加显式 `--observe-forceadapt-echo`，只可与 `--write` 加**一个**
  已命名固定候选同用，或与既有单侧 `--effect mild`（`--duration` 仍限
  0.1–2 秒）同用；拒绝 medium/strong、双侧和任意参数。默认路径不变。
  所有写入仍经 `RelayLock`、DeviceType、连接和 `0xFFA0` 接口验证。
- 初始双侧 Normal 后，在写入效果之前有界读取并丢弃此前排队的输入/`0xA0`
  echo，最多 100 ms；只为降低初始 Normal 回复混入后续窗口的可能性，不作为
  新设备命令。然后写固定效果，记录写入成功后的单调时刻 `t_effect`。
- 在同一 fd 上非阻塞观察最多 100 ms（且不得超过效果的既定截止时间），
  只统计格式有效且 `legacy.command_echo(data)==0xA0` 的帧。输出
  `A0_ECHO_OBSERVED` 或 `A0_ECHO_NOT_OBSERVED` 及观察区间；不输出 MAC、
  整帧或未解释的状态字节。因为回执可能延迟/丢失，结果只属诊断信号，
  不单独证明具体 mode 被固件应用。
- 效果绝对截止时间为 `t_effect + 原候选时长`；观察消耗其内部时间，不能
  顺延截止。无论观察成功、超时、异常或进程中断，都沿既有 `finally` 路径
  尝试双侧 Normal；清除失败继续返回非零并停止后续测试。若 echo 读取失败，
  标为 UNKNOWN，不用“未观察到”冒充设备拒绝。
- 同时运行物理-only 输入监视，先用 `umask 077` 和 `mktemp` 在独立验证目录
  建立 0600 文件，再通过 `tee` 保存**完整**输出；终端仅由过滤器显示
  `READY`/必要状态，不让高频事件挤掉工具输出。监视可在虚拟 Edge 暂停时继续读取
  物理 L2/R2。测试结束后仅用 `t_effect` 至 Normal 完成时刻筛选对应侧
  `ABS_BRAKE/ABS_GAS`，输出事件数、最小/最大值和至少一个完整按下/松开序列。
  原始输入文件保留在验证目录，不提交；项目证据只收脱敏摘要。

## 验证与决策

- 离线先写失败测试：参数组合限制、无额外写命令、同 fd `0xA0` echo 的
  观察/未观察/读取失败、绝对截止不滑动、Normal 失败非零；保留全部旧工具测试。
  本地和 SteamOS 的完整单测、编译及脚本检查通过后，才能作为诊断候选。
- 本规格本身不批准任何实体效果。下一次仅提交一个包含侧别、已知固定参数、
  最长时长、输入动作、自动 Normal、总预算和停损条件的授权包；持握者明确
  确认后才执行，游戏启动另行确认。
- 若写入期间无完整物理按放，触感阴性仍是“时序不充分”；若有按放而 echo
  未观察到，继续查回执通道而非立刻提高强度；若有按放和 echo 但仍无触感，
  才讨论手柄侧状态或分级强度的新授权。任一步有卡滞、错误侧或 Normal UNKNOWN
  立即停止。mode 1 在此之前保持不可默认开放，mode 3 也不因该诊断自动开放。
